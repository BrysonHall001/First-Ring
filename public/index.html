    Wiring this into the AST app

    The AST developer adds one outbound request and one inbound endpoint. That's the whole integration.

    1 · When a form with instant-call enabled receives a submission, AST calls:

    
    
    Authenticated with the X-AST-Key header (). The call is queued and dialed within the client's calling window.
    

    
    2 · When the call ends, this server posts the result to the client's AST webhook URL (set per client):
    
    
    POST {your AST endpoint}
Header  X-AST-Key: {same shared key}

{
  "astRecordId": "the candidate record to update",
  "callId": "call_ab12cd34ef",
  "disposition": "interested | voicemail | no_answer | callback_requested | not_interested",
  "summary": "Three-sentence recap written for the recruiter",
  "attempt": 1,
  "endedAt": "2026-08-26T14:03:22.000Z"
}
    
    
    AST writes those fields onto the candidate entry — same reporting, new columns.
    

    
    What's simulated right now
    
    
    The dial itself. Everything else — queueing, calling windows, retries, transcripts, dispositions, the AST webhook — runs for real, so the whole loop is demonstrable today. Swapping the simulator for a real Pipecat + Twilio dial changes one function on the server and nothing in this UI. The keys it will need live in .env (see .env.example).
